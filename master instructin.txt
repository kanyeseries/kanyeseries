==================================================

Login pages must include:

"Keep me logged in"

When checked:

    auth,
    browserLocalPersistence
);

When unchecked:

await setPersistence(
    auth,
    browserSessionPersistence
);

Then perform:

await signInWithEmailAndPassword(
    auth,
    email,
    password
);

IMPORTANT:

- Passwords
- Firebase tokens
- Login credentials

in:

- localStorage
- sessionStorage
- cookies

Firebase Authentication must manage authentication persistence.

const userRef = ref(db, `users/${user.uid}`);

await set(userRef, {
    uid: user.uid,
    name: name,
    email: user.email,
    phone: phone || "",
    photoURL: "",
    role: "customer",

13. CLOUDINARY UPLOADS
==================================================

Use Cloudinary for:

- Product images
- Profile images
- Special order images
- Other website images where appropriate

Do NOT use Firebase Storage.

Example:

const cloudinaryUploadUrl =
    "https://api.cloudinary.com/v1_1/fjifvpsp/image/upload";

const formData = new FormData();

formData.append("file", file);
formData.append("upload_preset", "kanye_products");

const response = await fetch(
    cloudinaryUploadUrl,
    {
        method: "POST",
        body: formData
    }
);

const data = await response.json();

After uploading:

1. Get the Cloudinary secure URL.
2. Store the URL in Firebase Realtime Database.
3. Use the URL to display the image.

19. REALTIME DATABASE OPERATIONS
==================================================

READ:

const snapshot = await get(
    ref(db, "products")
);


WRITE:

await set(
    ref(db, `products/${productId}`),
    productData
);


UPDATE:

await update(
    ref(db, `products/${productId}`),
    {
        price: newPrice
    }
);


DELETE:

await remove(
    ref(db, `products/${productId}`)
);


GENERATE ID:

const newProductRef = push(
    ref(db, "products")
);

const productId = newProductRef.key;

==================================================
23. FIREBASE SECURITY
==================================================

Frontend code is NOT security.

Use Firebase Realtime Database Security Rules to protect data.

User-specific data should be protected using:

auth.uid

Example concept:

{
    "rules": {
        "users": {
            "$uid": {
                ".read": "auth != null && auth.uid === $uid",
                ".write": "auth != null && auth.uid === $uid"
            }
        }
    }
}

Admin-only data must require proper authorization.

Never rely only on frontend checks.
